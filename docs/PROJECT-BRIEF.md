## 1. О проекте
Мобильное приложение-агрегатор: пользователь быстро находит ближайшие **автосервисы**
и **магазины запчастей**, смотрит варианты **списком или на карте**, связывается с продавцом.
- **Модель:** агрегатор (поиск → контакты → заявка). Задел под маркетплейс с оплатой/доставкой
  в будущих фазах (гибрид).
- **Регион:** СНГ / Армения. Карты — Яндекс. Валюта по умолчанию — AMD.
- **Аудитория:** и пожилые, и молодые. Приложение обязано быть максимально понятным и практичным.

## 2. Стек
- Мобильное: **Flutter** (один код на iOS + Android)
- Бэкенд: **NestJS** (TypeScript) — свой сервер, максимум контроля
- БД: **PostgreSQL 15+ / PostGIS 3+**
- Поиск по тексту: `pg_trgm` (старт) → Meilisearch (позже)
- Карты: **Yandex MapKit** (`yandex_mapkit`)
- Авторизация: по номеру телефона (SMS)
- Push: Firebase Cloud Messaging
- Хранилище фото: S3-совместимое
- Веб-панель продавца / админка: Next.js или Flutter Web

## 3. Цель MVP («хребет»)
Довести до конца сквозной путь:
**выбор авто (Марка → Модель → Поколение) → ближайшие магазины/сервисы списком и на Яндекс-карте.**
Сначала на тестовых данных, затем реальные продавцы.

## 4. Категории первой версии
- `repair_shop` — автосервисы (СТО). Проще: локация + услуги + телефон + часы.
- `parts_shop` — магазины запчастей. Сложнее: каталог товаров + совместимость с авто.
Обе работают на одном движке: геопоиск + витрина продавцов + селектор авто как фильтр.

## 5. Подбор запчастей (важно)
**Не точный TecDoc-подбор.** Прагматичный путь:
1. Совместимость указывает сам продавец → таблица `part_fitments`.
2. Поиск по **OEM/артикулу** для тех, кто знает номер.
3. Просмотр по категориям.
Выбор авто = фильтр. Точный подбор (лицензируемая база) — отдельная будущая фаза.

## 6. Дорожная карта
- Фаза 0 — фундамент: стек, схема БД, селектор авто, базовый геопоиск.
- Фаза 1 — MVP: repair_shop + parts_shop, список/карта, заявка/звонок, панель продавца, админка.
- Фаза 2 — оплата/доставка для товаров (маркетплейс, где оправдано).
- Позже — точный подбор запчастей; новые вертикали (шины, эвакуаторы).

## 7. Модель данных (полная — см. db/schema.sql)
Доступ к данным и авторизация контролируются в бэкенде (NestJS), RLS не используем.
- `users` — покупатели (id, phone, name, ...).
- `vendors` — продавцы; `type` ∈ {parts_shop, repair_shop};
  `location geography(Point,4326)` — ключ геопоиска; рейтинг, верификация, часы (jsonb).
- `car_makes` → `car_models` → `car_generations` — каталог авто (общий фильтр).
- `part_categories` — дерево категорий деталей (`parent_id`).
- `parts` — товары продавца: title, brand, `oem_number`, price, in_stock, photos[].
- `part_fitments` — совместимость от продавца: (part_id, make_id, model_id?, generation_id?).
  NULL у model/generation = «вся марка/вся модель».
- `service_categories` — справочник услуг СТО.
- `vendor_services` — услуги конкретного сервиса (price_from/price_to).
- `inquiries` — заявки покупателя (type part/service, статус, контекст авто).
- `reviews` — отзывы (1–5, уникально на пару user+vendor).
- `favorites` — избранные продавцы.
- `user_cars` — «Мой гараж» (сохранённые авто).
Индексы: GiST на `location`; btree на FK и `oem_number`; GIN/pg_trgm на `parts.title`.

## 8. Геопоиск (см. db/search_functions.sql)
Тяжёлая логика — в SQL-функциях, бэкенд вызывает их через `pg.Pool`.
- `search_parts(lat, lng, radius_m, make_id, model_id, category_id, query)`
  → ближайшие магазины с подходящей деталью; одна строка = один магазин (= маркер),
  плюс расстояние, число позиций, мин. цена, координаты.
- `search_repair(lat, lng, radius_m, service_category_id)` → ближайшие сервисы с услугой.
- **Порядок координат PostGIS:** `ST_MakePoint(lng, lat)` — сначала долгота.
- Функции возвращают `lat`/`lng` для меток на карте.

## 9. API
- `GET /search/parts?lat&lng&makeId&modelId&categoryId&radius&query`
- `GET /search/repair?lat&lng&serviceCategoryId&radius`
- Справочники: `/makes`, `/models?makeId`, `/generations?modelId`,
  `/part-categories`, `/service-categories`
- Карточка: `/vendors/:id`, `/parts/:id`
- Действия: `POST /inquiries`, `POST /reviews`, `/favorites`, `/user-cars`
- Валидация: глобальный `ValidationPipe({ transform: true, whitelist: true })`.
- Конфиг: `DATABASE_URL=postgres://user:pass@host:5432/autoapp`.

## 10. Экраны приложения
- Splash → запрос геолокации → Главная
- Главная: переключатель [Запчасти]/[Ремонт], поле поиска (артикул/название),
  кнопка «Выбрать авто» (или активное из Гаража)
- Выбор авто: Марка → Модель → Поколение/Год (списки с поиском)
- [Запчасти] категории деталей → результаты; [Ремонт] категории услуг → результаты
- Результаты: тумблер **Список ⇄ Яндекс-карта**, сортировка (расстояние/цена/рейтинг),
  фильтры (радиус, наличие, цена)
- Карточка продавца: инфо, часы, рейтинг, отзывы, услуги/товары,
  кнопки **Позвонить · Маршрут · Заявка**
- Карточка товара (запчасти)
- Профиль: Мой гараж, Избранное, Мои заявки, авторизация по телефону

## 11. Дизайн и доступность — НЕ нарушать
Аудитория — и пожилые, и молодые → читаемость и предсказуемость важнее «красоты».
- Крупный шрифт (база 16–18), поддержка системного увеличения текста
- Зоны нажатия ≥ 48 dp; кнопки действий от 56 px высотой
- Высокий контраст (текст ≥ 4.5:1); **никогда не полагаться только на цвет** — добавлять иконку/подпись
- Один главный шаг и одно главное действие на экране
- Минимум ввода: выбор авто тапами + «Мой гараж»
- Большие явные кнопки «Позвонить» и «Маршрут»; нижняя навигация с подписями
- Внятные пустые состояния и ошибки (что случилось + как исправить)
- Шрифт: **Inter** (через google_fonts), один характерный шрифт на всё
- Фирменные элементы: крупный **бейдж расстояния** («2.4 км») и чип **«Мой гараж»**
- Палитра «Asphalt & Signal» (см. mobile/lib/theme/app_theme.dart):
  - текст `#14181F` · первичный (синий) `#1E3A5F` · действие/CTA (янтарь) `#F5A300`
  - фон `#F4F6F8` · поверхности `#FFFFFF` · границы `#DDE3EA`
  - вторичный текст `#5B6672` · успех `#1E8E5A` · ошибка `#D23B3B`
Одна палитра — и в приложении, и в веб-панели.

## 12. Веб-панель продавца и админка
- Продавец: вход по телефону → профиль с точкой на карте → CRUD товаров/услуг + фото
  → лента входящих заявок (смена статуса) → отзывы.
- Админка: верификация/модерация продавцов, справочники (марки/модели, категории),
  жалобы, аналитика. На старте можно Retool / таблицы.

## 13. Каталог авто — источники
Старт: засеять топ-30–50 марок локального рынка + популярные модели/поколения
(бесплатные датасеты, NHTSA vPIC). Расширять по мере роста. Точная база — позже.

## 14. Чек-лист качества
- Индексы (GiST/btree/pg_trgm), пагинация результатов, кэш справочников, ресайз фото
- Безопасность: авторизация и проверки доступа в бэкенде; секреты не хранить в репо
- i18n с первого дня (армянский/русский/английский), мультивалютность
- Аналитика событий: поиск, открытие карточки, заявка, звонок
- Анти-спам для заявок и отзывов
- Юридическое: согласие на геолокацию, политика конфиденциальности, правила продавцов,
  требования App Store / Google Play

## 15. Конвенции кода
