# pg.Pool вместо ORM для гео

**Решение:** доступ к БД — сырой `pg.Pool` с параметризованным SQL; гео-логика в SQL-функциях. Никакого ORM.

**Почему:** TypeORM/Prisma некорректно мапят тип `geography`, ломают порядок координат и приведения; `ST_DWithin`/`ST_MakePoint` работают верно только в сыром SQL.

**Как применять:** вызовы вида `pool.query('SELECT * FROM search_parts($1,...)', [...])`. См. [[Параметризованный SQL везде]].
